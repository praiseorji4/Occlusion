# bno055.launch.py

Standalone launch file for the BNO055 IMU driver. This is used for isolated IMU testing and verification — it starts only the `bno055` node without any other robot hardware or controllers. It is separate from the main robot bringup.

There are two `bno055.launch.py` files in the workspace:

- **Vendored package default**: `src/bno055/launch/bno055.launch.py` — loads `bno055/config/bno055_params.yaml` (the package's own default YAML).
- **Deployment config** (used in `real_robot.launch.py`): the `bno055_node` defined there loads `ubot_bringup/config/bno055_params.yaml`, which overrides the P2 axis remap and other deployment-specific values.

The file documented here is the **vendored** `src/bno055/launch/bno055.launch.py`. It is the one invocable by name as shown below.

## Quick start

```bash
ros2 launch bno055 bno055.launch.py
```

## Arguments

None. This launch file does not declare any `DeclareLaunchArgument` entries.

## Launched nodes

| Node name | Package | Executable | Parameters |
|---|---|---|---|
| *(default — not named in Node())* | `bno055` | `bno055` | `bno055/config/bno055_params.yaml` |

The node is defined without an explicit `name=` argument, so it will use the executable name `bno055` as its ROS node name.

### Key config values from bno055_params.yaml

The vendored default config at `src/bno055/config/bno055_params.yaml` (and the deployment config at `src/ubot/ubot_bringup/config/bno055_params.yaml`) set the following:

| Parameter | Value | Notes |
|---|---|---|
| `connection_type` | `i2c` | I2C bus connection (not UART) |
| `i2c_bus` | `1` | `/dev/i2c-1` on Raspberry Pi |
| `i2c_addr` | `0x28` | Default BNO055 I2C address (ADR pin low) |
| `data_query_frequency` | `100` | Hz — sensor data polling rate |
| `calib_status_frequency` | `0.1` | Hz — calibration status check rate |
| `frame_id` | `imu_link` | Must match URDF link name |
| `operation_mode` | `0x0C` | NDOF (Nine Degrees Of Freedom) fusion mode |
| `placement_axis_remap` | `P2` | Physical mounting orientation (see BNO055 datasheet P0–P7 table) |
| `acc_factor` | `100.0` | Raw-to-SI conversion scale |
| `mag_factor` | `16000000.0` | Raw-to-SI conversion scale |
| `gyr_factor` | `900.0` | Raw-to-SI conversion scale |
| `grav_factor` | `100.0` | Raw-to-SI conversion scale |
| `set_offsets` | `false` | Do not write pre-calibrated offsets on startup |

Pre-calibrated offset values are present in the YAML (`offset_acc`, `offset_mag`, `offset_gyr`) but are only applied when `set_offsets: true`.

The covariance parameters (`variance_acc`, `variance_angular_vel`, etc.) are commented out in the deployment config, meaning the driver will use its compiled-in defaults.

## Published topics

| Topic | Message type | Description |
|---|---|---|
| `/bno055/imu_raw` | `sensor_msgs/Imu` | Raw (unfiltered) IMU data |
| `/bno055/imu` | `sensor_msgs/Imu` | Filtered quaternion + angular velocity + linear acceleration |
| `/bno055/mag` | `sensor_msgs/MagneticField` | Magnetometer reading |
| `/bno055/grav` | `geometry_msgs/Vector3` | Gravity vector (no covariance — message type limitation) |
| `/bno055/temp` | `sensor_msgs/Temperature` | On-chip temperature |
| `/bno055/calib_status` | `std_msgs/String` | JSON: `{sys, gyro, accel, mag}` calibration levels 0–3 |

## Services

| Service | Type | Description |
|---|---|---|
| `/bno055/calibration_request` | `std_srvs/Trigger` | Switch to config mode, read calibration data, return as response string |

## Verifying IMU operation

After launching, check calibration status first:

```bash
ros2 topic echo /bno055/calib_status
```

Wait until `sys` reaches 3 (full calibration). Then check the IMU data stream:

```bash
ros2 topic echo /bno055/imu
ros2 topic hz /bno055/imu   # should report ~100 Hz
```

To verify the axis remap is correct for your mounting orientation, check that gravity appears on the expected axis when the robot is on flat ground:

```bash
ros2 topic echo /bno055/grav
```

## Relationship to real_robot.launch.py

In `real_robot.launch.py`, a `bno055_node` is **defined** (lines 101–107) using the deployment YAML (`ubot_bringup/config/bno055_params.yaml`) but is **not included** in the returned `LaunchDescription` — the line adding it is commented out at line 125. Use this standalone launch file to test the IMU in isolation before enabling it in the main bringup.
